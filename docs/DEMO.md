## 展示前

1. 執行 `.\.venv\Scripts\python.exe -m pytest -q`，確認自己的版本通過測試。
2. 執行 `.\.venv\Scripts\python.exe -m streamlit run app.py`，開啟 <http://127.0.0.1:8501>。舊索引從本機文章自動升級，不需重新下載。
3. 確認目前文章數與讀取範圍。純數字／PMID 讀 PubMed 摘要，PMC 開頭讀 PMC 全文；摘要統計只計正文，單字數採空白分隔。
4. 搜尋與已存文章可離線操作；新下載需要網路。需要展示全文檢索時，另外準備一篇含正文的 XML，選擇僅出現在正文的詞作查詢。不要把四篇摘要的命中數套用到其他語料。

## 可核對的實測結果

需要展示批次新增時，先以一般模式啟動（`scripts/start_demo.ps1`），不要使用封鎖網路的離線測試啟動器。到「文章管理」→「PMID／PMCID 下載」，上傳每行一個 PMID 的 TXT（如 `pmid-covid-set.txt`），核對 10 筆預覽後按「批次下載並加入搜尋」。每 20 筆合併下載、最後統一建索引；此清單只需一次正常請求。完成後查看逐篇結果，再切到搜尋頁查詢。此步需要網路並會增加語料，下列四篇摘要的固定命中數與百分比不再適用；每個 PMID 仍讀摘要正文。若顯示離線展示提示，需關閉該程序並重新啟動一般模式，重新整理網頁不會解除封鎖。

2026-09-19 網頁固定使用 Porter，搜尋 `covid` 的順序為 PMC9080963、PMC8259047、PMC11462910，顯示 13%、10%、9%。數值雖與前一日原詞模式四捨五入後相同，底層分數不同。PMC8692081 的摘要沒有 covid，但含 SARS-CoV-2，所以 `SARS` 會找到它。詳細分數及片段見 [真實語料紀錄](../reports/default-porter-live.json)。

`vitamin A`、`vitamin C`、`hepatitis B`、`T cell` 的字母保護已用合成語料驗證，但目前真實文章庫未必含有這些名稱。沒有實際資料時不要宣稱應該命中；可以解釋有效關鍵字，或另用測試資料展示。

## 能獨立解釋的問題

- **倒排索引儲存什麼？** 搜尋詞／概念對應文件、詞頻、區塊與原文位置。有效詞命中聯集作候選，cosine 決定排序。
- **為何 `the` 不列文章？** 它是停用詞，過濾後沒有有效主題詞；單獨 `b` 則資訊不足。
- **為何保留 `vitamin A` 的 A？** 文件與查詢先檢查已登錄上下文，避免將名稱中的字母當成功能詞刪除。
- **為何 `covid` 找得到 COVID-19？** 文件依連字號、字母／數字交界建立完整詞與部分特徵，covid 命中其中一部分；IL6／IL-6、BRCA1 也適用，不用疾病別名表。
- **為何不混淆 HIV-1／HIV-2？** 查詢每個 token 保留完整條件，輸入 HIV-1 不會拆成「HIV 或 1」；只輸入 HIV 才能匹配兩者。此例已用合成語料驗證，不保證目前文章庫含有這兩種名稱。
- **分數為何和舊版不同？** 完整詞與有效部分均加入文件向量，文件範數與詞頻分布改變；公式仍為 TF-IDF cosine。
- **相關性怎麼算？** 對數 TF、平滑 IDF 與完整有效詞向量的 cosine。不是正確率或相關機率；沒有任意 10% 門檻。
- **Porter 做什麼？** 現在自動合併部分英文詞形，例如 antibody／antibodies；不代表理解同義詞，也不保證一定更準。therapy／therapies 已用合成語料驗證，目前四篇摘要沒有這兩個完整詞，不用它們宣稱應有命中。
- **字數會因過濾而變少嗎？** 不會。搜尋表示與原始統計分開；摘要字數仍按空白分隔，全文仍用原始 tokenizer。
- **有語意或引號搜尋嗎？** 網頁目前沒有語意模型、任意布林運算或引號片語功能。舊 AND／OR／PHRASE API／CLI 保留相容性。
- **AI 協助範圍？** Codex 協助實作、測試與文件；本人需理解方法、覆核來源及限制，並獨立展示。

文章刪除、還原與永久刪除展示請使用獨立測試資料目錄，保留自己的文章庫。不要手動移除刪除標記或進行中的 `purge_pending.json`。
