## 2026-09-21 修正離線誤用及批次下載速度

使用者回報全部 ConnectionError，程序命令列確認 8501 由 `scripts/run_offline_demo.py` 啟動；該腳本刻意阻擋非 loopback socket。失敗紀錄每篇約隔 7 秒，舊版仍逐篇重試，10 篇因而等待約 70 秒。一般程序直連同一 NCBI API 得到 HTTP 200，確認離線測試模式是此次連線阻擋的原因。

保留離線測試的封鎖功能，新增環境標記、下載頁提示及 UI／後端的立即阻擋；一般服務改用正常 Streamlit 指令重啟。批次下載改為每 20 筆一次 EFetch，按 PMID 對應回應並拆成單篇 XML，拒絕重複／缺少 ID 與非英文資料，避免失敗文章因 raw 同步混入。每篇保存文章，最後統一發布索引；中途連線失敗停止後續批次，已完成資料仍可載入。

完整回歸 **348 passed，39.09 秒**。相同真實 10 筆 PMID 在兩個獨立語料目錄比較：舊版 9.821 秒／10 次 HTTP，新版 1.452 秒／1 次 HTTP；兩者均 8 篇匯入、2 篇非英文失敗，標題、原文區塊、範圍、統計與 covid 搜尋排序／完整分數一致。這是單次本機端到端下載量測，不代表固定網路效能。詳見 [下載修正成果](../reports/RESULTS.md#2026-09-21-下載連線與速度修正)。
